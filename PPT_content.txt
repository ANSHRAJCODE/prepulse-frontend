SLIDE 2 — PROBLEM STATEMENT
-----------------------------
Heading: The Placement Process is Broken

Current problems:
• Placement officers manage 500+ students manually in spreadsheets
• No way to instantly know which students are eligible for which company
• Students don't know what skills they are missing until rejection
• Companies receive unfiltered applications — no intelligent ranking
• Feedback loop is slow — students get no guidance until too late

Result: Low placement rates, missed opportunities, wasted time

Visual: Simple diagram showing manual process vs automated process

SLIDE 3 — SOLUTION OVERVIEW
-----------------------------
Heading: PrepPulse — Intelligent Placement Infrastructure

PrepPulse is a full-stack web application that:
✓ Automatically matches students to jobs using a weighted algorithm
✓ Identifies skill gaps in real time for every student-job pair
✓ Generates personalised AI learning roadmaps using a local LLM
✓ Gives placement officers a live analytics dashboard
✓ Allows companies to post jobs and get auto-ranked candidate lists

Visual: Screenshot of student dashboard showing match scores

SLIDE 4 — TECH STACK
----------------------
Heading: Technology Stack

Backend:
  • FastAPI (Python) — REST API with JWT authentication
  • SQLAlchemy ORM — database abstraction layer
  • PostgreSQL — production database (Render cloud)
  • Ollama + Llama 3.2:3b — local AI, zero API cost

Frontend:
  • React 18 + Vite — fast, component-based UI
  • Zustand — lightweight state management
  • Recharts — data visualisation and charts

Deployment:
  • Render — backend + PostgreSQL (free tier)
  • Vercel — frontend (free tier, CDN, instant deploys)

SLIDE 6 — CORE FEATURE: MATCH ENGINE
--------------------------------------
Heading: Intelligent Match Engine

How it works:
1. Student fills profile: CGPA, skills, branch, certifications
2. Company posts job: required skills, min CGPA, eligible branches
3. Match engine runs for every student-job pair:

   Score = (Skill Match % × 0.5) + (CGPA Score × 0.3) + (Branch × 0.2)

4. Students ranked automatically — top matches shown first
5. Missing skills highlighted in red for the student to see

Result: Placement officers see an instant ranked list.
        Students see exactly what they need to improve.

SLIDE 7 — CORE FEATURE: AI ROADMAP
-------------------------------------
Heading: Local AI Learning Roadmaps

When a student's match score is below threshold:
• System detects missing skills
• Sends student profile + job requirements to Ollama (Llama 3.2:3b)
• AI generates a personalised 3-step learning plan
• Plan includes: what to learn, resources, timeline

Why local LLM?
✓ Zero API cost — runs on college server
✓ No data privacy concerns — student data stays on campus
✓ Works offline — no internet dependency for AI feature

SLIDE 8 — THREE ROLE SYSTEM
-----------------------------
Heading: One Platform, Three Perspectives

STUDENT ROLE
• View dashboard with CGPA, skills, application count
• Browse all active job listings with match scores
• Apply to eligible jobs with one click
• Get AI roadmap for skill gap closure
• Track application status in real time

ADMIN ROLE
• Placement Command Center with batch analytics
• Department-wise readiness heatmap (% ready per branch)
• All students table with drill-down (applied, placed, etc.)
• Application pipeline chart (applied → shortlisted → placed)

COMPANY ROLE
• Post jobs with skill criteria and CGPA cutoff
• View auto-ranked candidate list for each job
• Update candidate status (shortlisted, interview, placed)
• Edit, close, or delete job postings

SLIDE 9 — SOFTWARE ENGINEERING PRACTICES
------------------------------------------
Heading: Engineering Practices Applied

Architecture Patterns:
• MVC — Model (SQLAlchemy), View (React), Controller (FastAPI routes)
• Service Layer — match engine and AI logic separated from routes
• Repository Pattern — database operations abstracted via ORM

Development Practices:
• Version Control — Git with separate frontend/backend repositories
• Environment Config — .env files, no hardcoded secrets
• Input Validation — Pydantic schemas on all API endpoints
• Error Handling — HTTP exceptions with meaningful messages
• CORS Policy — configured for production domains only

Deployment:
• CI/CD — GitHub push triggers automatic Render + Vercel deploy
• Database migrations — Alembic for schema management
• Seed data — automated database population on startup
